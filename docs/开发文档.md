地方非遗文化AI解码与传承平台（移动端）开发文档
文档版本：V1.0
编制日期：2026年10月
开发模式：跨平台移动端开发（UniApp + 后端服务分离架构）
适配终端：安卓APP、iOS APP、微信小程序、移动端H5（一套代码多端发布）
项目定位：以地方非遗数字化保护与青年化传播为核心的移动端AI互动平台，以扬州非遗为落地示例，融合知识图谱、多模态AIGC、语音导览与游戏化科普四大能力，主打移动端轻量化、沉浸式、可分享的非遗文化体验。
1. 项目概述
1.1 项目背景
非物质文化遗产是中华传统文化的核心载体，但当前非遗数字化传播普遍存在三大痛点：
呈现形式静态化：多为PC端文字+图片资料库，缺乏移动端适配与互动性，难以触达年轻群体；
知识关联碎片化：项目、传承人、技艺、历史、民俗等信息相互独立，未形成完整的文化脉络；
参与门槛较高：普通用户只能被动观看，无法参与非遗创作，文化传播缺乏沉浸感与传播力。
本项目以UniApp跨平台技术为载体，以AI技术为核心，打造“可查询、可互动、可创作、可游玩、可分享”的移动端活态非遗传承平台，兼具文化价值、技术价值与社会价值。
1.2 项目目标
跨端覆盖：一套代码同时发布安卓APP、iOS APP、微信小程序、H5四个终端，降低开发成本；
数字化解码：构建结构化的地方非遗知识图谱，在移动端实现文化脉络的可视化呈现；
AI化互动：通过多模态生成技术，零门槛支持用户生成非遗风格纹样、剧本、画作；
轻量化传播：语音导览、扫码观展、分享传播等移动端原生能力，降低非遗文化接触门槛；
可落地复用：模块化设计，可快速适配不同地区非遗资源，具备推广价值。
1.3 项目价值
社会价值：活化地方非遗资源，助力非遗数字化保护与青年化传播，推动文化普惠；
技术价值：覆盖跨平台开发、知识图谱、多模态AIGC、可视化交互、游戏化设计等全栈技术；
实训价值：功能模块边界清晰，难度分层合理，适合团队分工开发，移动端演示效果突出；
传播价值：微信小程序端无需安装，扫码即用，适配线下非遗馆、校园科普等真实场景。
1.4 受众定位
核心受众：青少年学生、文化爱好者、游客；
使用场景：线上浏览学习、线下展馆导览、社交分享传播、校园科普活动；
管理端：非遗保护工作人员、文化馆运营人员（Web端管理后台复用）。
2. 需求分析
2.1 功能性需求
2.1.1 非遗知识图谱与可视化模块
非遗项目全库检索：按类别、级别、地区筛选查询非遗项目详情；
传承人谱系展示：展示项目传承代际、代表传承人、传承流派；
文化脉络可视化：以力导向图、时间线形式呈现非遗历史演变与关联关系；
实体关联跳转：点击任意实体可跳转查看详情与关联内容；
移动端适配：支持双指缩放、单指拖拽、点击弹出详情卡片。
2.1.2 AI互动创作模块
非遗纹样生成：输入关键词，生成剪纸、漆器、玉雕等风格的装饰纹样；
非遗剧本生成：输入主题，自动生成非遗科普短剧脚本，支持方言台词；
非遗风格画作生成：支持拍照上传/相册选图、文字描述两种输入方式，生成非遗风格画作；
作品管理：保存历史生成记录，支持一键保存到手机相册、分享到微信/朋友圈。
2.1.3 多模态智能导览模块
自动语音讲解：点击项目自动播放标准讲解词，支持倍速、字幕同步；
多语种/方言切换：普通话、地方方言双模式讲解；
智能问答：支持按住说话语音提问，系统智能解答并语音播报；
扫码导览：调用手机摄像头扫描展品二维码，直接跳转对应项目详情与讲解。
2.1.4 非遗科普闯关模块
关卡体系：设置多个段位与主题关卡，难度逐级提升；
智能出题：基于知识库动态生成选择题、判断题、图片识别题；
积分与成就：答题累计积分，解锁成就徽章与科普彩蛋；
排行榜：展示用户积分排名，支持分享成绩。
2.1.5 个人中心模块
用户信息管理：头像、昵称设置；
我的作品：AI生成的所有作品历史记录；
我的错题：答错的题目与知识点解析；
收藏功能：收藏非遗项目与传承人；
离线缓存：可下载核心讲解音频与基础数据，无网环境使用。
2.1.6 后台管理模块（Web端复用）
内容管理：非遗项目、传承人、多媒体素材的增删改查；
用户管理：用户信息、积分、权限管理；
数据统计：访问量、创作量、答题数据可视化统计；
AI配置：模型参数、Prompt模板、生成风格配置。
2.2 非功能性需求
性能需求：APP首屏启动≤2s；页面切换≤1s；知识图谱渲染≤2s；文本生成响应≤5s；图像生成响应≤30s；
易用性需求：符合移动端交互习惯，底部Tab导航，大点击区域，青少年无需引导即可上手；
兼容性需求：
安卓：兼容Android 8.0及以上主流机型；
iOS：兼容iOS 13.0及以上；
微信小程序：兼容最新版微信基础库；
可扩展性需求：模块化架构，支持新增非遗类别、新增AI能力、扩展地区数据；
数据安全与版权合规：所有公开素材标注来源，非商业用途；用户数据加密存储；AI生成内容标注“AI创作”标识。
3. 系统总体架构
3.1 架构设计原则
前后端完全分离：移动端负责交互与展示，后端负责业务逻辑与数据处理，多端共用一套后端服务；
跨平台统一开发：基于UniApp框架，一套代码编译多端，通过条件编译处理平台差异；
服务化分层：AI能力独立封装为服务，便于替换与升级；
轻量化优先：学生实训场景优先采用开源免费技术与轻量部署方案。

3.3 核心业务流程
知识查询流程：移动端检索→后端匹配数据→查询图数据库→返回实体与关系→移动端可视化渲染；
AI创作流程：移动端输入创作需求→后端调用对应AI模型→生成结果→存储并返回移动端展示；
科普答题流程：用户进入关卡→后端拉取题目→用户作答→判分并更新积分→解锁下一关；
扫码导览流程：移动端调用摄像头扫码→解析项目ID→请求后端详情数据→加载页面与讲解音频。
4. 核心功能模块详细设计（移动端适配版）
4.1 非遗知识图谱可视化子系统
4.1.1 功能定义
以图结构存储非遗领域知识，通过力导向图、时间线等形式，在移动端直观呈现非遗文化的内在关联，支持触控交互。
4.1.2 功能细分
全景图谱：展示选定区域内所有非遗项目的分类关系、传承网络；
移动端优化：默认展示核心节点，避免小屏拥挤；支持双指缩放、单指平移；点击节点弹出详情卡片，而非跳转新页面。
项目详情图谱：单个项目的历史脉络、技艺流程、传承人谱系、代表作品、关联民俗；
时空地图：结合地图展示非遗项目的地理分布，按朝代展示历史演变；
智能关联推荐：查看某项目时，底部推荐相似技艺、同时期非遗、同地域文化。
4.1.3 技术实现逻辑
实体抽取：基于官方名录结构化数据 + 大模型NER抽取，从非遗介绍文本中提取实体；
关系定义：预设9类核心关系（传承、归属、盛行于、使用材料、创作、关联民俗等）；
可视化渲染：采用uCharts（UniApp生态图表库）+ 自定义Canvas实现力导向图，原生支持触控事件。
4.2 AI互动创作子系统
4.2.1 功能定义
基于多模态AIGC技术，让用户在手机端零门槛参与非遗风格创作，支持拍照生成、一键分享，实现“人人都是非遗传承人”的互动体验。
4.2.2 功能细分
非遗纹样生成
支持风格：扬州剪纸、漆器纹样、玉雕图案、蓝印花布等；
输入方式：文字关键词描述；
输出：高清纹样图，支持保存相册、分享微信。
非遗科普剧本生成
输入主题、时长、角色数量，自动生成短剧脚本；
支持方言台词适配、分镜头提示；
可复制文本，用于短视频拍摄、校园话剧。
非遗风格画作生成
支持两种模式：文生图（文字描述）、图生图（拍照/相册选图）；
风格模型：漆画、水墨画、年画、刺绣等地方非遗美术风格；
生成结果自动标注风格来源与AI创作标识。
4.2.3 关键实现点
Prompt工程：为每种非遗风格定制专属Prompt，融入工艺特点、色彩特征、构图规则；
风格增强：图像生成采用“基础大模型 + 非遗风格LoRA”方案，提升风格还原度；
移动端交互：调用uni.chooseImage API实现拍照与相册选图；生成过程展示加载动画与进度提示。
4.3 多模态智能导览子系统
4.3.1 功能定义
为线上数字展与线下非遗馆提供移动端智能语音讲解与问答服务，结合扫码能力，实现“线下扫码、线上听讲解”的智慧导览体验。
4.3.2 功能细分
自动语音讲解：标准讲解词由专业文案+大模型润色生成，支持倍速调节、字幕同步显示；
方言讲解：支持本地方言版本讲解，贴近老年群体与本地受众；
智能问答：支持按住说话语音输入，RAG检索知识库后大模型组织答案，语音播报回复；
扫码导览：调用手机摄像头扫描二维码，直接跳转对应非遗项目详情页与语音讲解。
4.3.3 技术实现逻辑
语音识别：集成uni语音识别插件 / 讯飞语音SDK，实现语音转文字；
语音合成：预生成标准讲解音频存储在服务端，流式播放；实时问答采用在线TTS合成；
扫码能力：调用uni.scanCode API，解析二维码中的项目ID参数，跳转对应页面。
4.4 非遗科普闯关子系统
4.4.1 功能定义
以游戏化闯关形式普及非遗知识，适配移动端触控交互，提升用户学习兴趣，尤其适配青少年群体与校园科普场景。
4.4.2 功能细分
关卡体系：设置“入门学徒”“匠人弟子”“非遗大师”等多个段位，每个段位对应多个主题关卡；
题目类型：选择题、判断题、图片识别题；选项放大点击区域，适配手指触控；
激励体系：答题得积分，积分解锁成就徽章、非遗彩蛋故事、限定创作素材；
错题本：自动收录答错题目，提供知识点解析，支持回顾复习；
分享功能：通关成绩、成就徽章可一键分享到微信，邀请好友挑战。
4.4.3 题目生成逻辑
基础题库：从官方非遗知识库中提取核心知识点，生成标准化题目；
动态出题：大模型基于RAG检索到的知识点，按照设定题型与难度生成新题；
难度控制：根据关卡等级调整题目深度，入门题考基础认知，进阶题考技艺细节与历史背景。

6. 数据库设计
6.1 设计说明
数据库全部部署在服务端，移动端不存储核心业务数据，仅缓存基础数据与离线资源；

:Heritage 非遗项目：id, name, level, category, region
:Inheritor 传承人：id, name, title
:Dynasty 朝代：name, start_year, end_year

:Work 代表作品：name, type

核心关系类型
[:INHERITS]：传承人 → 非遗项目

[:PREVAILED_IN]：非遗项目 → 朝代

[:CREATED]：传承人 → 代表作品
[:ASSOCIATED_WITH]：非遗项目 → 民俗
7. 核心API接口设计
统一采用RESTful风格，基础路径：/api/v1，返回格式统一为JSON，安卓、iOS、小程序、H5多端共用同一套接口。
7.1 知识图谱接口
获取非遗分类列表
GET /heritage/categories
返回：所有非遗类别及对应项目数量
获取知识图谱数据
GET /knowledge-graph
请求参数：category（可选）、region（可选）、depth（默认2）
返回：{ nodes: [], edges: [] } 节点与边列表
获取非遗项目详情
GET /heritage/{id}
返回：项目完整信息、关联传承人、关联作品、关联民俗
7.2 AI创作接口
生成非遗纹样
POST /ai/generate-pattern
请求体：
{
"prompt": "梅花主题",
"style": "扬州剪纸",
"size": "1024x1024"
}
返回：生成图片URL、任务ID
生成科普剧本
POST /ai/generate-script
请求体：
{
"theme": "漆器制作流程",
"duration": 60,
"dialect": false
}
返回：剧本文本、分角色台词
7.3 导览服务接口
获取讲解音频
GET /audio/guide/{projectId}
请求参数：lang（mandarin/dialect）
返回：音频文件流
智能问答
POST /audio/qa
请求体：{ "question": "扬州剪纸有多少年历史？" }
返回：文字答案 + 语音音频URL
7.4 科普游戏接口
获取关卡列表
GET /game/levels
返回：所有关卡信息、解锁状态
获取关卡题目
GET /game/questions/{levelId}
请求参数：count（默认10）
返回：题目列表（不含答案）
提交答案
POST /game/submit
请求体：{ "questionId": 1, "answer": "A" }
返回：是否正确、答案解析、本次得分、总积分
7.5 用户接口
用户登录/注册
POST /user/login
请求体：{ "openid": "xxx", "nickname": "xxx", "avatar": "xxx" }
返回：用户信息、token
获取用户信息
GET /user/info
请求头：Authorization: Bearer {token}
返回：用户积分、收藏、错题等数据
8. 移动端打包与原生能力扩展
8.1 多端编译策略
基于UniApp的条件编译机制，一套代码处理平台差异：
安卓/iOS APP：完整功能，支持摄像头、语音、离线下载、推送、保存相册等全部原生能力；
微信小程序：适配小程序域名校验、文件存储限制，分享能力复用微信原生分享；
H5：轻量化版本，适配手机浏览器，部分原生能力降级实现。
8.2 核心原生能力调用

| 能力 | 调用方式 | 适用平台 |
| --- | --- | --- |
| 拍照/相册选图 | uni.chooseImage | 全平台 |
| 扫码 | uni.scanCode | APP、小程序 |
| 语音录制/识别 | 讯飞语音插件 / uni.getRecorderManager | 全平台 |

| 分享到微信 | uni.share / 微信小程序分享API | APP、小程序 |
| 离线缓存下载 | uni.downloadFile + 本地文件系统 | 全平台 |
| 消息推送 | uni-push 2.0 | APP |

8.3 APP打包流程
开发调试：HBuilderX中运行项目，使用真机调试或模拟器调试功能；
发行打包：
安卓：点击「发行 → 原生App-云打包」，选择安卓平台，配置APP名称、图标、启动页，使用免费云打包生成APK文件；
iOS：需苹果开发者账号，同理云打包生成IPA文件；
测试安装：安卓APK可直接发送到手机安装，iOS通过TestFlight分发测试。
8.4 微信小程序发布流程
HBuilderX中点击「发行 → 小程序-微信」，编译生成小程序代码包；
微信开发者工具中导入代码，配置合法域名，上传代码；
微信公众平台提交审核，审核通过后发布。

12. 风险识别与应对措施

| 风险点 | 影响程度 | 应对措施 |
| --- | --- | --- |

| 开发进度滞后 | 高 | 采用MVP原则，优先实现核心功能（知识图谱+AI纹样+答题），裁剪次要功能 |
| 云打包次数限制 | 低 | 开发阶段多用真机调试，最终发布再使用云打包；或使用本地打包环境 |

RAG：检索增强生成，通过检索知识库提升大模型回答的准确性；
